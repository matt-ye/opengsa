# 規劃與待辦

最後更新：2026-11-10。做完的項目移到對應的 PR 或查核紀錄，這裡只留還沒做的。

## 已定案的決定（2026-11-10）

- **第 2 階段先做 54 所沒有卡的學校**：78 校名冊中目前沒有任何卡片的 54 校先探索，已有卡的 24 校之後再處理。設計見 [docs/UNIVERSITY-DISCOVERY-DESIGN.md](UNIVERSITY-DISCOVERY-DESIGN.md)。
- **ReAct D（找入口頁）先試模型版本，失敗時退回關鍵字規則**。模型只看連結文字和頁面標題，不送內文。
- **探索預算每輪 100 次請求**，另外算，不吃每日巡檢的 50 次。
- **核可流程**：使用者在 Issue 勾選要加入的網域後，由代理開核可 PR（把網域加進 `allowed_hosts`、入口頁設為來源），使用者再合併。
- **取消「生輔組只能人工查核」的舊規定**：生輔組頁面和其他來源一樣，依 robots 與白名單規則處理；robots 不允許的路徑仍然不抓。

## 已定案的決定（2026-11-09）

- **審核節奏**：資料 PR 每週彙整一次。週一那輪開 PR，內容是整週累積的待審；週二到週六只掃描。
- **每輪上限**：變動文件 10 份、待審 60 份。原為 5 份與 24 份。
- **陌生來源探索**：先做全台大專校院，之後再做縣市社會局、部會與基金會。
- **模型**：列入規劃，用來練習「提高專案適應性」的方法。原則如下：
  - 規則優先，模型只補規則做不到的地方。
  - 模型的輸出都要經過規則驗證；出處對不上原文就丟掉。
  - 只用免費額度的模型池（`auto_pool`），每輪有呼叫上限。
  - 只能看 `hash_only` 原文的來源，原文一律不送出。
  - 開啟前先用評測集量準確度。

## 第 0 階段：穩定運行（這週）

- **觀察排程**：每天看一次。週一那輪要確認三件事：資料 PR 有開出、`status/` 狀態檔有寫入、收件匣 #116 有通知。
- **巡檢第一圈**：上限調到 10 之後，第一圈約 20 輪，以每週 6 輪計約 3–4 週。

## 第 1 階段：品質收尾（1–2 週）

萃取與資料：

- **FAOS 時程規則**：`faos-agency-months`、`faos-ntu-paper-days` 已撤下，等重新核對。
- **同一方案的多份文件**：例如輔仁不利處境助學金的公告和辦法，現在各成一張卡。改用頁面之間的連結關係（公告連到辦法）歸成同一方案，不靠標題比對。
- **評測集持續擴充**：每次抽查確認過的頁面都加進 `data/eval/page-expectations.json`。改萃取規則前後各跑一次 `scripts/evaluate_pages.py`。

模型（階段 1 的後續，仍是離線實驗，不接排程）：

- **階段 1 結果**：標題選擇節點的第一次實驗已完成（PR #125），整體不比規則好，不全面開啟；結果與原因見 [docs/AGENTIC-EXTRACTION-ARCHITECTURE.md](AGENTIC-EXTRACTION-ARCHITECTURE.md) 第 6 節。
- **標題節點第二版**：只在規則選到的標題看起來像單位名稱或口號時才呼叫模型，規則標題可用時不准回答「都不是」；腳本要跟轉址（第一版讀到 Azure 的轉址頁）。
- **案例紀錄格式**：把每次「規則錯、模型對」的案例記成固定格式，用來找出該叫模型的條件、再寫回規則和評測集。
- **接上 `model_limits`**：讓 adapter 從 `status/model-catalog.json` 和 `data/model-providers.json` 取得各家限制。

## 第 3 階段：審核效率（第 2 階段之後）

- **單張卡駁回**：在資料 PR 留言 `/reject <卡片 id> <原因>`，由 workflow 寫進台帳並從 PR 拿掉，不必整個 PR 都不合併。
- **週報摘要**：每週那份資料 PR 的說明由結構化差異產生，列出新增幾張、更新幾張、各來自哪些網站、哪些欄位有變。
- **模型輔助（可選）**：請模型標出值得人工細看的卡，例如金額或截止日跟上一版差很多。只用結構化差異，不送原文。

## 第 4 階段：模型修正迴圈（等標題節點第二版量測有結果）

- **觸發條件**：規則讀到頁面卻沒成卡，而且原因是 `title_not_a_program` 或 `no_eligibility_sentence`。
- **做法**：請模型提出標題和資格，必須附上原文出處；接著照樣跑 `verify_candidates`，沒過就丟掉。
- **節省呼叫**：依內容雜湊快取，內容沒變就不再呼叫。每輪有呼叫上限，用量記在 `model-usage.json`。
- **開啟條件**：先在評測集上離線量準確度，達標才接進排程。使用者決定開啟時機。
