# 19筆雷達資料顯示落差盤查

2026-11-01，沿用既存候選快照；沒有重新GET來源、呼叫模型、改正式pilot或代填核准。本輪是顯示與欄位對應修正，不宣稱新增萃取事實。

## 原因與修正

| 問題 | 實際原因 | 本輪處理 |
|---|---|---|
| HTML／PDF文件候選、待整併出現在名稱 | `candidate_preview_data`額外拼入流程文字 | 保留原始名稱，版本與相關文件另列，ID仍各自獨立 |
| 承辦單位全部不明 | 前台只讀`receiver.url`，既有fact結構主要為`text`與`refs`，13筆已有收件／轉送文字、0筆獨立單位網址 | 顯示其中12筆原記錄收件／轉送摘要；1筆全國法規誤沿用臺大收件路徑先隔離。無獨立網址連原文，不把收件角色冒充具名承辦人 |
| 地方AI補助對象變不明 | 含「須依各條件核對」便整段隱藏 | 保留粗略對象與限制，對象摘要由11增至13筆；不代表完整個人資格符合 |
| 相對時間與校院期限看不見 | 卡片只取學生截止；部分說明含「尚待」又被整段替換 | 保留各層角色，7筆有已支持的期限／相對規則可顯示；其中學生時間仍僅3筆，不能將其他層級回填為學生截止 |
| 註記條件造成整段消失 | `radarFact`用關鍵字任意位置比對 | 只有空值與完整預設提示才轉未知；已有內容中的待核限制原樣保留 |
| 未知提示太長 | 每個欄位重複完整句子 | 黃色警示圖示＋「不明，請見來源 ↗」，保留可讀文字、提示與官方連結 |

比對是同一候選快照經修改前／後的`makeDrafts`投影，不是模型正確率；19張文件仍19張，13組方案仍13組。

## 真正尚未萃取的內容

6筆身分仍是`身分條件請至來源定位核對`，對應千里馬、中研院博士獎學金、國科會研究人力、電資博士獎學金、TA制度HTML與PDF。它們走`_extract_policy`，此函式目前直接設定通用提示；找到文字區塊／證據定位不等於已產生正確身分摘要。同6筆相關單位仍為「待查」，不是多個單位無法選一個。不能靠呈現層把預設博士身分或來源網站名稱升格為萃取結果。

另發現`_extract_nstc_conference`的舊規則將臺大路徑與國科會全國法規的receiver共用；後者範圍是國內合格機構，卻記錄「學生先送臺大」。本輪顯示層以學校範圍隔離這1筆錯路徑，仍顯示有證據的機構／補件時間；原解析器已分開兩種路徑並升為extractor-1.4.2，合成雙路徑測試通過。本輪未重掃或改原候選，下輪須取得新鮮來源全文重新檢核後更新快照，不把顯示層隱藏當資料已修正；舊計畫／核准不沿用。

現有Schema的細分有用途：`organizations`分資助／公告／收件，`schedule.steps`支援多角色，`application_start`有certainty；不必為了卡片把它們壓回單一欄位。已知單位文字附有來源refs，但既有單位解析多為具名方案規則，未有逐角色語意正確率基準，本輪不宣稱完成通用承辦人辨識或新增聯絡電話。

下一輪萃取優先順序：

1. 在已準備好的來源區塊中，依申請／受益／約用角色擷取短身分摘要，明確區分多種約用身分；缺證據繼續未知。
2. 在本方案章節辨識「送交／洽詢／承辦／受理」及對應單位，逐角色留證據；多單位可按角色並列，不強選一個、不抓頁尾總機當承辦電話。
3. 各時程按學生／系所／學院／校級／機構／補件保留；常態月日、購買期限、推估日期與固定受理窗口分開。院系未公告期限仍不能推測。
4. 對目前6筆通用預設來源建立正負例，再有限重掃驗證來源版本及證據；來源受阻維持人工查核，不從零碎摘錄補寫全文結論。

## 日期顯示與判斷邊界

官方開始、學生截止、校院送件、機構期限、補件規則可並列。已記錄且有證據的inferred／tentative起日，僅在另行標示「推估開始（非官方起日）」的位置呈現；不放入正式起日、不用來判定開放。這批沒有可新增的推估起日，不依公告日自行製造。

地方工具補助仍明示年度最晚上限及可能更早的個人期限；相對會議規則未提供會議日不編固定日期。增加可讀時間不增加「受理中」判定。
